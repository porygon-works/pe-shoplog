## 1. 目的と前提

### 1.1 目的
社員が普段の店選びに困ったときに見る、社内向けのお店ログ（食べログのようなもの）。
★評価は付けず、「実際に行ったらどうだったか」（喫煙、値段感、何に使ったか、写真、コメント）を共有することを重視する。

### 1.2 前提・制約
- 個人製作の非公式ツール。上層部の承認は取らない。
- 利用者は社員のみ。ログイン必須。アクセス元は制限しない（スマホからどこでも見られる）。
- スマホで使う前提。PWA にして、ホーム画面に追加できるようにする。
- 構成: Next.js 16（App Router）＋ Vercel（Hobby プラン）＋ Supabase（DB・認証・Storage、Free プラン）＋ Google Maps Platform。
- Vercel Hobby は規約上「個人の非商用利用」限定。小規模な非公式ツールとして始め、規模が大きくなったら Pro へ上げる（リスクは承知の上で決定済み）。
- 運用者は 1 人（管理者）。費用は最小限にする。

### 1.3 成功の条件
- 店名だけで、数タップで「気になる店」を登録できる。
- 店のページを開けば、喫煙・値段感・使った用途・写真・コメントが一目で分かる。
- 他の人の公開リストや、みんなで作る共有リストから店を選べる。

## 2. 用語

| 用語 | 意味 |
|---|---|
| お店 | 全員で共有する店の情報（店名、場所、ジャンル、形態、参考リンク） |
| 行った記録 | 1 人が 1 回行ったときの記録（喫煙、値段感、用途、コメント、写真など）。1 店に何件でも付く |
| 気になる店 | 行った記録が 0 件のお店（未開拓） |
| マイリスト | 個人が持つリスト。種類は「気になる」「お気に入り」。公開・非公開を選べる |
| 共有リスト | 複数人で一緒に編集するリスト。招待リンクで参加する |
| 不明 | 選択項目で何も選ばなかった状態。全項目の既定値 |

## 3. 画面構成

画面下にタブを 4 つ置く: **マップ / さがす / ＋登録 / マイページ**

### 3.1 マップ
- Google マップを表示する。Google 標準の店舗アイコン（飲食店など）はそのまま表示し、登録済みのお店には専用ピンを重ねる。
  - ピンは 2 種類: 行った記録あり / 気になる（未訪問）。
  - 飲食以外の施設アイコンは、Map ID のクラウドスタイルで非表示にする。
- 絞り込み: ジャンル、店の形態、喫煙、値段感、用途、「気になるだけ」。条件は URL クエリに保持する（nuqs）。
- 登録済みのピンをタップすると、店の概要カード（店名、ジャンル、代表的な喫煙・値段感、記録件数）を出す。カードから店の詳細ページへ移動する。
- 未登録の Google 店舗アイコンをタップすると、「この店を登録」カードを出す。

### 3.2 さがす
タブを 2 つ置く。

- **お店タブ**: 店名のキーワード検索と、マップと同じ絞り込み。並び順は新着順・記録の多い順。
- **リストタブ**: 公開されているマイリストと共有リストを一覧する。並び順は更新順・店の多い順。開くと、リスト内の店が並ぶ。

### 3.3 ＋登録
1. 店を選ぶ。Google の店舗検索（オートコンプリート）か、マップ上の店舗アイコンのタップで選ぶ。Google にない店は手入力でき、その場合は位置をマップ上で指定する。
2. 店名が自動で入る（編集可）。ジャンル・形態・参考リンクは任意。
3. 登録先を選ぶ。
   - **「気になる」で登録**: お店を作成し、自分の既定の「気になる」リストに入れる。
   - **「行った記録を付ける」**: お店を作成したあと、記録の入力画面へ進む。
- すでに同じ店（同じ place_id）が登録されていれば、新規登録はせず、既存の店の詳細ページへ案内する。
- 必須項目は店名だけ。

### 3.4 店の詳細ページ
- 店名、ジャンル、形態
- 集計（§5.3）: 喫煙、値段感、用途の内訳（例: 打ち上げ ×2、チーム会議 ×1）、最大人数、予約の要否、支払い方法
- 写真ギャラリー（メニュー / 席 / 料理 / 外観 で切り替え）
- 行った記録とコメントの一覧（新しい順）
- ボタン類
  - 「気になる」「お気に入り」: リスト選択シートを開く。既定のリストが選択済みの状態で開く。
  - 「＋リストに追加」: マイリストと共有リストの両方から選ぶ。
  - 「行った記録を付ける」
  - 「🌐 公式サイト」: タップした時だけ Google からサイト URL を取得して開く（§7.3）。
  - 「Google マップで開く」: 経路案内用。place_id を使った URL で開く（API 課金なし）。
  - 予約・参考リンク: ユーザーが入力したもの。
- 店情報（店名・ジャンル・形態・参考リンク）は、ログインユーザーなら誰でも編集できる。

### 3.5 行った記録の入力
選択項目はすべてチップ（タップで選ぶボタン）。何も選ばなければ「不明」。

| 項目 | 形式 | 選択肢 |
|---|---|---|
| 行った日 | 日付 | 既定は今日 |
| 喫煙 | 単一選択 | 喫煙可 / 分煙・喫煙室あり / 加熱式のみ / 禁煙 / 不明 |
| 値段感（1 人あたり） | 単一選択 | 〜2,999 / 3,000〜4,999 / 5,000〜6,999 / 7,000〜9,999 / 10,000〜 / 不明 |
| 用途（実際に使ったもの） | 単一選択 | チーム会議 / 社員総会 / 打ち上げ / 歓送迎会 / 同期のみ / 接待 / プライベート / その他 / 不明 |
| 人数 | 数値（任意） | 何人で行ったか |
| 予約 | 単一選択 | 予約した / 予約なしで入れた / 不明 |
| 支払い方法 | 複数選択 | クレジットカード / QR決済 / 交通系IC / 現金のみ / 不明（何も選ばない） |
| コメント | テキスト（任意、1,000 文字まで） | おすすめ料理・いまいちだった点など |
| 写真 | 画像（任意、10 枚まで） | 1 枚ごとに種類を選ぶ: メニュー / 席 / 料理 / 外観 / その他 |

- 記録の編集・削除は、本人と管理者だけができる。

### 3.6 マイページ
- **マイリストタブ**: 自分のリストの一覧。作成、名前の変更、公開・非公開の切り替え、削除ができる。
- **共有リストタブ**: 自分が参加している共有リストの一覧。作成もここから行う。
- **自分の記録**: 自分が付けた記録の一覧。
- **アカウント**: ニックネームの変更、パスワードの変更、ログアウト。
- 他のユーザーのページ（ニックネームから開く）では、その人の公開リストと記録が見られる。

### 3.7 共有リスト
- 作成者がオーナーになる。作成すると招待リンクが発行される。
- 招待リンクを開いたログインユーザーは、ワンタップでメンバーとして参加できる。
- オーナーは招待リンクを作り直せる（古いリンクは無効になる）。
- メンバーは全員、店の追加と削除ができる。追加するときに一言メモを付けられる。
- オーナーはメンバーを外せる。リストの名前・説明・公開設定の変更と、リストの削除もオーナーだけができる。
- メンバーは自分で抜けられる。
- 「公開」にすると、メンバー以外も閲覧だけできる。

### 3.8 管理画面（管理者のみ）
- 合言葉の変更
- ユーザーの仮パスワード発行（パスワードを忘れた人向け）
- ユーザーの停止・削除
- お店・記録・写真の削除（論理削除）
- 管理者権限の付与。最初の管理者は DB で直接設定する。

## 4. 認証

### 4.1 新規登録
- 入力項目: ユーザーID、ニックネーム、パスワード、合言葉（画面では「いつもの2文字を入れてね」と案内する）。
- ユーザーID: 半角英小文字・数字・`_`、3〜20 文字。重複不可。後から変更不可。
- ニックネーム: 1〜20 文字。重複可。後から変更可。
- パスワード: 8 文字以上。
- 合言葉: 大文字・小文字を区別しない。

### 4.2 仕組み
- Supabase Auth はメールアドレスが必須のため、`{ユーザーID}@users.pe-shoplog.invalid` という届かないダミーアドレスに変換して登録する。ユーザーにアドレスは見せない。
- Supabase の公開サインアップは **無効** にする。登録は必ず Server Action 経由で行う。
  1. 入力チェックと、試行回数の制限（同じ IP から 1 時間に 10 回まで。試行記録は DB テーブルに残す）。
  2. 合言葉の照合。合言葉はハッシュ化して `app_settings` テーブルに置き、secret キーでしか読めないようにする。
  3. secret キーで `auth.admin.createUser`（メール確認済み扱い）を呼び、`profiles` を作成する。
  4. 既定のマイリスト「気になる」「お気に入り」（どちらも非公開）を作成する。
  5. そのままログインさせる。
- 公開サインアップを無効にしているので、ブラウザ用キーで Supabase に直接登録して合言葉を回避することはできない。
- ログイン: ユーザーIDとパスワードを入力し、サーバー側でダミーアドレスに変換して `signInWithPassword` を呼ぶ。
- パスワードを忘れた場合は、管理者が仮パスワードを発行する（メールでの再設定はできない）。
- サーバー側の認証確認は `getClaims()` で行う。

## 5. データ設計

### 5.1 テーブル
共通ルール:
- 主キーは `uuid`。
- `created_at` / `updated_at` を持つ。
- ユーザーが作るデータは `deleted_at` で論理削除する。

| テーブル | 主な列 |
|---|---|
| `profiles` | `id`（auth.users と 1:1）, `login_id`（unique）, `nickname`, `is_admin`, `disabled_at` |
| `shops` | `place_id`（unique、NULL 可 = 手入力の店）, `name`, `lat`, `lng`, `location_fetched_at`, `genre`, `styles text[]`, `reference_url`, `created_by` |
| `visits` | `shop_id`, `user_id`, `visited_on`, `smoking`, `price_range`, `purpose`, `party_size`, `reservation`, `payment_methods text[]`, `comment` |
| `photos` | `visit_id`, `shop_id`, `user_id`, `kind`, `storage_path`, `width`, `height` |
| `lists` | `owner_id`, `name`, `kind`（want / favorite）, `is_public`, `is_default` |
| `list_items` | `list_id`, `shop_id`, `added_at`（`(list_id, shop_id)` で unique） |
| `shared_lists` | `owner_id`, `name`, `description`, `is_public`, `invite_token`（unique） |
| `shared_list_members` | `shared_list_id`, `user_id`, `role`（owner / member）, `joined_at` |
| `shared_list_items` | `shared_list_id`, `shop_id`, `added_by`, `note`, `added_at`（`(shared_list_id, shop_id)` で unique） |
| `app_settings` | `key`, `value`（合言葉ハッシュなど。RLS で全拒否し、secret キーでのみ操作する） |
| `signup_attempts` | `ip`, `attempted_at` |

- 選択肢の値は Postgres の enum ではなく、`text` と CHECK 制約で持つ。選択肢の追加をマイグレーション 1 本で済ませるため。「不明」は `unknown` という値で表す。
- ジャンルと形態の選択肢はコード側の定数で管理する（管理画面からは編集しない）。
  - ジャンル: 和食 / 寿司・海鮮 / 焼肉・ホルモン / 焼き鳥・串 / 鍋 / 中華 / 韓国 / アジア・エスニック / イタリアン / フレンチ・ビストロ / 洋食 / ラーメン / カレー / カフェ / その他 / 不明
  - 形態: 大衆居酒屋 / 居酒屋 / ダイニングバー / バー / 立ち飲み / 個室あり / カラオケ / その他

### 5.2 アクセス制御（RLS）
全テーブルで RLS を有効にする。ログインしていないユーザーは何も読めない。
`auth.uid()` は `(select auth.uid())` と書き、ポリシーで使う列にはインデックスを張る。

| 対象 | 読み取り | 作成 | 更新・削除 |
|---|---|---|---|
| profiles | ログインユーザー全員 | （サーバーのみ） | 本人（ニックネーム）、管理者 |
| shops | 全員（`deleted_at is null`） | 全員 | 更新は全員、論理削除は管理者 |
| visits / photos | 全員 | 本人 | 本人、管理者 |
| lists / list_items | 公開リストは全員、非公開リストは本人のみ | 本人 | 本人 |
| shared_lists / items | メンバー、または公開リストなら全員 | メンバー（items） | items はメンバー、リスト本体はオーナー |
| shared_list_members | メンバー同士、公開リストなら全員 | 招待トークン経由（SECURITY DEFINER 関数） | 本人が抜ける、オーナーが外す |

- 管理者判定は SECURITY DEFINER 関数 `is_admin()` で行う。
- shops で一般ユーザーが更新できるのは `name, genre, styles, reference_url` のみとする（列単位の GRANT で制限する）。`deleted_at`・`place_id`・位置情報は変更できない。
- 停止したユーザー（`disabled_at` が入っている）は、Supabase Auth 側でも BAN する。

### 5.3 集計の決め方
集計ビューは `security_invoker = true` で作る。

- **喫煙**: 「不明」以外で最も新しい記録の値（店の喫煙ルールは変わるため）。全件の内訳も表示する。
- **値段感**: 「不明」以外で最も多い値。同数なら新しい方。
- **用途**: 件数の内訳。絞り込みでは、該当する記録が 1 件でもあれば一致とする。
- **人数**: 最大値。
- **予約・支払い方法**: 件数の内訳。

### 5.4 写真
- Storage の非公開バケット `photos` に保存する。パスは `shops/{shop_id}/visits/{visit_id}/{uuid}.jpg`。
- アップロード前にブラウザの canvas で長辺 1600px の JPEG（品質 0.8）に変換する。これで EXIF（撮影位置）も消える。
- 表示には署名付き URL（有効期限 1 時間）を使い、まとめて発行する。
- 写真ごとに個別にアップロードし、失敗した写真だけ再送できるようにする。

## 6. 処理の流れ

- 読み取りは Server Components から Supabase（ユーザーのセッション、publishable キー）で行う。
- 書き込みは Server Actions（`useActionState`）で行う。写真だけは、ブラウザから Storage に直接アップロードする（RLS で本人のパスのみ許可）。
- Google Places の呼び出しは Route Handler（`app/api/places/*`）経由にし、ログイン済みユーザーだけが呼べるようにする。
- `proxy.ts` のマッチャーから、`api/`・`sw.js`・`manifest.webmanifest`・静的アセットを除外する（プレイブックの教訓 #4・#7）。
- 戻るボタンは、同じサイト内から来た場合だけ履歴を戻る。直接開いた場合はホームへ移動する。

## 7. Google Maps Platform

### 7.1 キー
- **ブラウザ用**: HTTP リファラ制限をかけ、Maps JavaScript API だけを許可する。マーカーに AdvancedMarker を使うため、Map ID も用意する。
- **サーバー用**: Places API (New) だけを許可する。Vercel の環境変数にのみ置く。
- Google Cloud 側で、予算アラートと API ごとの 1 日あたり上限を設定する。

### 7.2 呼び出しとフィールドマスク
| 用途 | API | 取得するフィールド |
|---|---|---|
| 店舗検索 | Autocomplete (New)。セッショントークンを使う | 候補の店名・place_id |
| 店を選んだとき | Place Details | `id, displayName, location` |
| 公式サイト（タップ時のみ） | Place Details | `websiteUri` |
| 位置情報の更新（日次バッチ） | Place Details | `location` |

### 7.3 データの保存ルール
- `place_id` は無期限に保存してよい。
- 緯度経度は 30 日までしか保存できないため、`location_fetched_at` を持ち、日次のバッチで 25 日を過ぎたものを取り直す。手入力の店（place_id なし）はユーザーが指定した位置なので対象外。
- 店名は、Google の値を初期値としてユーザーが確認・編集して登録する、ユーザーのデータとして扱う。
- サイト URL・住所・営業時間・評価は保存しない。サイト URL はその都度取得する。
- 外部 API が失敗したら、トーストやエラー表示で画面に出す。無言で 0 件にはしない。

## 8. 運用

- **ホスティング**: Vercel Hobby。関数のリージョンは `hnd1`（東京）。GitHub と連携し、main に push したら本番に反映される。
- **Supabase**: このアプリ専用のプロジェクトを東京リージョンに作る。新しい API キー（publishable / secret）を使う。
- **日次の GitHub Actions**:
  1. `supabase db dump` を実行し、Actions の artifact として 90 日間保存する。
  2. 緯度経度の更新バッチを呼ぶ（`/api/cron/refresh-locations`。シークレットトークンで保護する）。
  - 毎日 DB にアクセスするので、Free プランの「7日間アクセスがないと一時停止」も避けられる。
- **CI**: push と PR ごとに、ESLint（flat config）・型チェック・Vitest・ビルドを実行する。
- **秘密情報**: `.gitignore` に `.env*.local` を入れる。GitHub の push protection を有効にする。
- README に、初期設定（Supabase、Google Cloud、Vercel の環境変数、最初の管理者の設定、合言葉の初期値）の手順を書く。

## 9. テスト
- **Vitest（単体テスト）**: 集計ロジック、入力チェック（ユーザーID・合言葉）、ダミーアドレスへの変換、画像の縮小で求めるサイズの計算。
- **RLS テスト**: ローカルの Supabase（`supabase start`）に対して実行する。
  - 非公開リストが他人に見えない。
  - 他人の記録を編集できない。
  - 共有リストのメンバー以外は書き込めない。
  - 公開サインアップが無効になっている。
- **Playwright（E2E）**: 新規登録 → 気になる店の登録 → 記録の追加（写真付き）→ リストへの追加 → 共有リストへの招待と参加。
  - ログイン状態（storageState）は使い回す。
  - Google API は Route Handler をモックして呼ばない。
