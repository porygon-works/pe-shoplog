## タスク B: 区分（ジャンル・形態）を管理画面から追加・編集できるようにする（Sonnet）

### 方針
- 選択肢をコード定数（`GENRES` / `STYLES`）から DB テーブル `shop_categories` に移す。値（`value`）は不変の ID、表示名（`label`）は編集可。
- 削除はしない（既存の店が参照しているため）。代わりに「非表示」にすると新規の選択肢から消える。既存の店の表示はそのまま。
- 既存の値（`washoku` など）はそのまま種データとして入れるので、既存の店のデータは変更しない。
- 本番 DB に影響する変更はすべて追加的に行う（列・データの削除はしない）。CHECK 制約だけはトリガーでの検証に置き換える。

### マイグレーション `supabase/migrations/0007_shop_categories.sql`
- `public.shop_categories`:
  `id uuid pk default gen_random_uuid()`, `kind text not null check (kind in ('genre','style'))`, `value text not null check (value ~ '^[a-z0-9_]{1,40}$')`, `label text not null check (char_length(btrim(label)) between 1 and 20)`, `sort_order int not null default 0`, `hidden boolean not null default false`, `created_at`, `updated_at`（`set_updated_at` トリガー）、`unique (kind, value)`。
- 種データ: 今の `GENRES` / `STYLES` を同じ value・label・並び順で insert（`on conflict do nothing`）。
- RLS: select はログインユーザー全員。insert / update は `public.is_admin()` のときだけ。delete のポリシーは作らない。
- `shops` の CHECK 制約（genre と styles。名前は `pg_constraint` で確認し、`alter table ... drop constraint if exists`）を外し、`before insert or update of genre, styles` のトリガーで「`genre` が kind='genre' に存在する」「`styles` の各要素が kind='style' に存在する」を検証（非表示でも存在すれば可）。違反時は `raise exception using errcode = '23514'`。
- 既存の DB テスト（`tests/db`）の CHECK 制約前提があれば合わせて直す。

### アプリ
- `src/lib/categories.ts`（server-only）: `getCategories()` を React の `cache` で 1 リクエスト 1 回だけ取得。戻り値 `{ genres: Category[], styles: Category[] }`（`Category = { value, label, hidden, sortOrder }`、sort_order→label 順）。
- クライアント用: `src/components/categories-provider.tsx` に Context と `useCategories()`。`src/app/(app)/layout.tsx` で取得して Provider に渡す。
- `GENRES` / `STYLES` を使っている箇所をすべて置き換える（`grep -rn "GENRES\|STYLES" src`）:
  - 選択 UI（`/new` の登録フォーム、`/shops/[id]/edit`、絞り込みシート）は非表示を除いた選択肢。編集画面では、今の値が非表示でもチップに残して選択状態を保つ。
  - 表示（店カード、店詳細）は非表示も含めて label を引く。見つからなければ value をそのまま出す（`labelOf` の今の挙動）。
  - 絞り込みのクエリ解析（`shop-filters.ts`）は、固定の許可リストではなく `^[a-z0-9_]{1,40}$` の形だけ検査し、存在しない値は結果 0 件で害はない形にする。
  - 検証（`validation.ts`）は genre/styles を形式チェックに緩め、Server Action（登録・編集）で `getCategories()` に対して存在チェック（新規選択は非表示不可、編集時は元の値なら非表示でも可）。
  - `options.ts` から `GENRES` / `STYLES` を削除。`options.test.ts` など関連テストも更新。
- 管理画面: `/admin/categories`（`requireAdmin`）。`/admin` に「ジャンル・形態の編集」へのリンク。
  - 「ジャンル」「形態」の 2 セクション。各行: 表示名（その場で編集して保存）、↑↓ で並べ替え、表示/非表示の切り替え、使っている店の数。
  - 末尾に「追加」フォーム（表示名だけ入力。value はサーバーで `c_` + ランダム 8 桁の 16 進で生成）。同じ kind で同じ表示名（非表示含む）は追加・改名不可。
  - `genre` の `unknown`（不明）は非表示にできない（未選択時の既定値のため）。
  - Server Actions（`src/app/(app)/admin/categories/actions.ts`）は必ず `requireAdmin()`。成功後 `revalidatePath("/", "layout")`。
- 登録・編集画面のジャンルの下の説明文に「選択肢は管理者が追加・変更できます」は不要（一般ユーザーには関係ない）。

### テスト
- unit: 追加時の value 生成、表示名の検証。
- db（`tests/db`）: 一般ユーザーは insert/update できない、管理者はできる、存在しない genre/style の店は insert できない、非表示の値は既存の店で保持できる。
- e2e: 管理者がジャンルを追加 → `/new` のチップに出る → その店の詳細に表示名が出る。非表示にすると `/new` から消える。

## タスク G: 昼／夜の時間帯区分（Sonnet）
- 店に時間帯区分を持たせる。値は `lunch`（昼）/ `dinner`（夜）。1 店に複数可。既存の店はすべて「夜」。
- マイグレーション `0009_shop_time_slots.sql`（追加的変更のみ）:
  - `shops.time_slots text[] not null default '{dinner}'`、CHECK `time_slots <@ array['lunch','dinner']::text[] and cardinality(time_slots) >= 1`。既存行は default で `{dinner}` になる（念のため update も入れる）。
  - authenticated に `grant update (time_slots) on public.shops`（店情報の編集は列単位の GRANT）。
  - `shop_index` は `s.*` で作られているので、`create or replace view` では列の順序を保ったまま **末尾に** `time_slots` を足す必要がある。今の列順（本番で確認済み）:
    `id, place_id, name, lat, lng, location_fetched_at, genre, styles, reference_url, created_by, created_at, updated_at, deleted_at, visit_count, last_visited_on, smoking, price_range, purposes, max_party_size, avg_rating, rating_count`
    → `s.*` をやめて、この順に列を明示し、最後に `s.time_slots` を足す。集計部分の定義は 0008 のものをそのまま使う。`security_invoker = true` も維持。
- 選択肢は `src/lib/options.ts` に `TIME_SLOTS = [{value:"lunch",label:"昼"},{value:"dinner",label:"夜"}]`。
- 登録（`/new` のフォーム、地図の未登録店カードのワンタップ登録は既定の「夜」）と店の編集画面に「時間帯（複数可）」のチップ。未選択は不可（最低 1 つ）。既定は「夜」。検証（validation.ts と Server Action）も。
- 表示: 店の詳細・店カードのジャンル行に「昼・夜」などを足す（ジャンル・形態の並びに含める程度で目立たせすぎない）。
- 絞り込み: `shop-filters.ts` に `time`（URL パラメータ `time`、配列、値は lunch/dinner）を追加し、`time_slots` と重なる店（`overlaps`）に絞る。`src/components/shop-filter-sheet.tsx` の `FILTER_KEYS` に `"time"`（ラベル「時間帯」）を **`want` の後ろ** に追加（マップの既定順で気になるの後ろ、さがすの 3 列グリッドでは 7 個目＝3 行目になる）。
- テスト: unit（validation、フィルタの解析）、db（CHECK、既定値、overlaps の絞り込み、shop_index に time_slots）、e2e（昼を付けて登録 → 時間帯「昼」で絞ると出る／「夜」では出ない）。
